# Methodology

## 2026-09-05：1.1.1 模拟器验收与发布

发布采用固定顺序：冻结源码并归档主机证据 → 隔离包生成数据验收 → 正式签名/品牌校验 → 正式包受控覆盖安装与回读哈希 → 精确白名单提交 APK/报告/校验文件 → GitHub Release 与匿名下载校验。测试数据、源码和签名材料不得进入分发仓库。

1. 从原工程正式发布目录选择已签名、已验证的 APK，不重新构建或覆盖原始产物。
2. 对复制前后的 APK 执行 SHA-256 比对。
3. 使用 Android Build Tools 校验签名、包名、版本和 SDK 信息。
4. 在独立 Git 仓库中提交分发文件，避免把原工程源码、构建缓存、密钥或账本数据一并上传。
5. 将 APK 同时作为仓库文件和 GitHub Release Asset 发布，并在 README 记录验证边界。

## 1.1.0 增量发布方法

- 先核对 GitHub API 的规范仓库名称、权限、远程分支及本地干净状态，不能仅依赖旧 owner 名。
- 原报告只读，整理独立公开版：保留升级/备份语义、最终验收与已知问题，移除本机路径和签名凭据处理细节。
- 修改前备份分发文档；只显式暂存发布文件，不提交源码工程的其他改动或本地验证日志。
- 仓库保留中文 APK 文件名，Release 附件采用 ASCII 文件名；上传后比对 GitHub asset SHA-256，并检查匿名下载和报告访问。
